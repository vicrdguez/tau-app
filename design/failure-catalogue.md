# Failure catalogue

The ways this client can mislead or fail its user, each with its defence and the check that keeps it. **Render** checks run on the client's own layout (rune's element tree and pixels, as the prototype's families did). **Fixture** checks feed `fixture.json` to the client and compare what it shows (`client.md` §9). **Unit** checks test one module. **Lint** is `keymap.toml`'s lint (`reference/grammar.md` §12). **Trial** means a person must try it.

## Answering (FA)

| ID | Failure | Defence | Check |
|---|---|---|---|
| FA1 | An answer is sent without the readback being read (`␣ad2y` typed as a burst) | `y` counts only after the readback has been on screen for 400 ms (`tau.client_ms.readback_arm`); an earlier `y` is discarded with `read it first`; each pick redraws and `y` waits for that draw | Unit: key queues at 80–150 ms intervals and at 500 ms; Trial: fast typing |
| FA2 | A click, `⏎` or auto-repeat confirms an answer | only a fresh `y` confirms; a click echoes `press y to confirm` | Unit; Render: the `y` chip has no click handler that sends |
| FA3 | An answer lands on a request that changed while the user read it | the readback turns off when the inbox changes the subject; the call quotes the decision ID and basis it drew; the server refuses `not_open` | Fixture: `streams.inbox.later[2]` with the readback open |
| FA4 | Two devices answer differently and the second user thinks theirs counted | `conflict` becomes the reply `Not recorded. phone answered …`, and the view takes the reply's `decision` at once (answered, no Answer, no diamond); notes stay as drafts | Fixture: `refusals.conflict …` |
| FA5 | A lost reply makes the user answer again with a different choice | `␣ad` is off while the answer is unknown; drafts stay; the client settles the entry from the inbox and `decision`; else `␣ar` sends the stored body through the readback | Fixture: a timed-out answer, then the inbox and `decision` that prove it landed |
| FA6 | A resend restarts work after a fault without the user's say | answers are never resent by the outbox or automatically; only `␣ar`, through the readback | Unit: the resend table in `client.md` §2.1; Lint: KL4g |
| FA7 | A note lands on the wrong passage | ranges are UTF-16 code units of `text`; a selection across markup widens to whole blocks and the note's head says so; `␣ts` gives exact ranges; the passage carries its tint, and a displaced note its leader | Unit: range mapping on the fixture's design text, including the code block and the table; Render: each note's leader ends at its passage's first line |
| FA8 | An answer sent from a row, the sidebar or the outbox, without the basis on screen | `␣ad` and `␣ar` exist only in the Decision view; any command whose `wire` includes `answer` must be decide-tier under `␣a` | Lint: KL4 (never a list context), KL4g; `tools/keymap-mutants.toml` |
| FA9 | A faulted `then` task is never noticed | it shows in Home's Failed, the Faults place and the sidebar's decision mark; the decision refetches its `then` state when shown, after its own answer, when a `faults` poll names it, and every 30 s until terminal | Fixture: `calls.faults render-core`, `decision render-core/w1:6:design#1` |
| FA10 | A `then` task's state shows a word the user can't read, or the wrong one | the table of `spec.md` §5.6 covers every status and outcome; anything else shows the raw word | Unit: each status, each outcome, and an unknown value |
| FA11 | The coral Answer invites `␣ad` while the keys are elsewhere | one rule (`spec.md` §4.6): the Answer is solid only when `␣ad` would open the readback; in Insert, under a float, and with the sidebar holding the keys it is a muted outline and its chip is inert | Render: DIM on `decision-note-insert`, `readback-answer` and `sidebar-focus-decision` |

## Connection (FC)

| ID | Failure | Defence | Check |
|---|---|---|---|
| FC1 | A proxy's 409 or 408 page is read as a refusal | only the body decides; anything but `result`, `refused` or `unknown` is unknown | Unit: replies with odd bodies and statuses |
| FC2 | A retried `input` sends the text twice | one request ID per send, resent unchanged; the server returns the first submission | Fixture: `local.outbox` unknown input, resend, one queue item |
| FC3 | A retried or repeated `create` makes a second conversation | `create` is never resent automatically, and its `input` waits for its result; from the press until `create` replies `⌘⏎` is off, the text is read-only and auto-repeat never fires; empty text sends nothing; after a lost reply the start page keeps the text and says a conversation may have been created | Unit: two presses 50 ms apart, and a held key, send one `create`; a timeout sends no `input` and no second `create`; Render: `start-starting`, `start-no-reply`; Fixture: `calls."create w1 render-core"` timing out |
| FC4 | A second `stop` ends a newer run | `␣cx` only in the conversation's own view, while the drawn frame shows a run; off after sending; never resent | Unit; Fixture: `stop` then a new run in `pi.live`; Lint: `conv.stop` only in context `conversation` |
| FC5 | Entries missed while asleep never appear, or a first open pages the whole history | the gap rule compares with what was held before the frame and skips when nothing was held | Fixture: `examples."gap rule"` (one `history` sequence) and `examples."gap rule, first open"` (none) |
| FC6 | A sleeping laptop shows a live-looking but dead view | a sleep-counting clock for the 45 s rule; every stream reopens on wake; the server line says `reconnecting` | Trial: close the lid with a run going |
| FC7 | A revoked device keeps retrying or looks connected | `end: revoked` freezes views, stops retries, shows the notice | Fixture: `streams.ends.revoked` |
| FC8 | A failing store's stream reopens forever without saying so | after 3 `failed` ends in a row, a notice band; for the inbox, one that says open decisions may be out of date for every project | Unit: three `failed` ends on `timeline` and on `inbox` |
| FC9 | A reconnect replays or invents events | the first frame replaces the value; nothing is replayed; a cut generation may shrink | Fixture: `open` first frame after `later` frames equals a fresh one |
| FC10 | The token leaks, or pairing over plain HTTP goes ahead unread | Keychain only; never in a URL, file or log; the Server float never shows it; before pairing over `http://` to a host that isn't loopback, a warning under the field and the Confirm float `Pair over plain HTTP? …`, where only `y` goes on; the form never prints `y`, which is a letter there | Unit: grep logs and config after pairing; Render: `connect-http-warning` with the Confirm float |
| FC11 | A server restarted without `--allow-host` is read as a revoke | any `unauthorized` shows the server's sentence and holds writes; "revoked" only after `end: revoked` | Fixture: `refusals."unauthorized (revoked)"` on a call with no `end` |
| FC12 | A stale input starts a run days later, or a stale option overwrites a newer one | automatic resends stop after 6 tries, never after 10 minutes or a restart; `setModel` and `setOptions` are never resent after a restart | Unit: entries aged 9 and 11 minutes, and restored from a launch |
| FC13 | A lost `pair` reply leaves the user stuck on a used name | Connect says the name may be used, to pair a new name and revoke the old one | Render: the Connect state |
| FC14 | Running and failed conversations are missed in a big project | `conversations` is read to the last page on every poll, newest shown first | Fixture: `calls."conversations render-core (two pages)"` |
| FC15 | A hidden sidebar hides server trouble | while the sidebar is not drawn, any abnormal server state (`○ connecting` included) shows at the bottom bar's right end in the server line's words; notice bands sit in the stage whatever the sidebar does | Render: PRESENCE: an abnormal link shows the server's words in exactly one visible place, with a seeded fault that removes them; `server-stopped` with the sidebar hidden; Fixture: `local.sidebarVisible` false with `streams.ends.stopping` |

## Content and spoofing (FS)

| ID | Failure | Defence | Check |
|---|---|---|---|
| FS1 | Agent or extension text poses as chrome (`◆ Needs you`, `ok`, a coral word) | rows and titles are one plain line after the client's own mark; content has no fills, chips, icons, containers or coral; Markdown only in content containers | Render: SPOOF and CORAL families on the fixture and on `conversation-hostile` (fixture `hostile`) |
| FS2 | A message fakes a tool success | tool rows come only from tool-call records and `pi.live.tools`, between messages; their outcome never comes from parsing output; a code block printing `✓ exit 0` stays a neutral code block | Render: `conversation-hostile`: a fenced `✓ exit 0` in agent text, and a call whose output says `✓ exit 0` with `isError: true`, which reads `failed` |
| FS3 | A workflow's input passes as the user's own | every `pi.user` entry is `input`, never "you"; a record says `by a task`, never what kind of task | Render: `conversation-hostile`, an input that opens `you:` |
| FS4 | Hidden characters change what a sentence says | bidi, zero-width and control characters render as visible escapes | Unit; Render: `conversation-hostile` (U+202E, U+202C, U+200B) |
| FS5 | A long label hides the row's identity | the label is cut, never the project or `#id`; in the sidebar, never the `#id` or `#n`; a faulted task's `after <decision ID>` shows whole or not at all, and its kind is cut first | Render: IDS family, the `after` span included; `home-1300`; `conversation-hostile`'s 262-character label |
| FS6 | A page title is mistaken for a document heading, or a heading for the page title | `title.page` is coral 24/30 with no rule, always the stage's first line with its facts line under it; a content `h1` is rose 20/28 with a rule, at least 24 px lower; content renders only in `prose.*`, so a basis or a message that opens with `# Needs you` gets a rose ruled heading, and a label `# Needs you` is a plain title | Render: SPOOF on `conversation-hostile` and the `hostile` decision (basis opening `# Review the design`): no content block in `title.page`, the first content heading below the facts line |

## Keys and targets (FK)

| ID | Failure | Defence | Check |
|---|---|---|---|
| FK1 | A key acts on a row that moved under it | keys resolve against the last drawn frame; the cursor is tied to an object ID | Unit: an insert above the cursor between draw and key |
| FK2 | A server event opens a float, moves focus, or adds, closes or reorders an open item | no server event does any of these; it may only turn an action off or change a mark | Lint: KL0 (no host triggers); Unit: an inbox change while the sidebar has the keys |
| FK3 | A printed key does nothing where it is printed | KL17 at render, strict in Insert, on a table generated from `keymap.toml` with its builtin sets; each chip's context and mode come from the region and the badge the render shows, never from a label it declares | Render: RESOLVE family |
| FK4 | Too many keys printed | the chip budget: 3 in the stage, 1 in the bottom bar, the sidebar's 2 | Render: CHIPS family |
| FK5 | A float hides what it is about | the page scrolls the target above it; a conversation's queue and composer lift | Render: the `unknown-outcome` and `readback-answer` states |
| FK6 | Notes are hard to discover | `␣mn` in which-key, the first-note ghost `+ note c`, the margin's head | Trial: a first decision with notes, unaided |
| FK7 | A bare `⏎` in the composer or the start page sends something that can't be taken back | `⌘⏎` sends; bare `⏎` is a new line in both | Lint: `composer.send` and `start.send` bind only `<D-CR>`; Unit |
| FK8 | Stop or continue from a list acts on a polled, stale state | both work only in the conversation's own view | Lint: their context is `conversation` only |
| FK9 | Two coral cursors show, or a coral cursor shows where the keys aren't | one region has the keys (stage, sidebar or float); only it draws a coral bar, coral head or coral caret; a float that takes the keys turns the others neutral, and one without a selection shows none; the bar is drawn inside the column | Render: CURSOR family on visible pixels: exactly one coral cursor per render, or none only under a float without a selection (`readback-send-again`, `answer-conflict`); `sidebar-focus`, `sidebar-focus-decision`, the pickers, `decision-note-insert` |
| FK10 | The start page sends to the wrong project or workflow | the project is the one the current view names (Project view, conversation, decision, sidebar item), else the last used; the start line names the project and the workflow (or model) before you type; `⌘⏎` sends what the drawn line named; after sending, the breadcrumb and the sidebar group name the project | Unit: `␣cn` from a `notes-cli` conversation starts in `notes-cli`; a project change between draw and `⌘⏎` doesn't change the call; Render: `start`, `start-project-picker`; Fixture: `calls."create w1 render-core"` |
| FK11 | A workflow that can't start eats the text, or is refused with no reason shown | the start line says `needs options: …` or `options don't fit: …` before you type, from the `options` item's `errors`, the server's own trigger; `⌘⏎` opens the options at the first field with an error and keeps the text; a refused `create` keeps it too | Render: `start-options-unset`; Fixture: `calls."options render-core (reviewer model gone)"`, `refusals."options_invalid (create w1 in render-core, a model the server no longer has)"` |
| FK12 | A float prints keys that don't work in its focused part | the bind float's hints follow the focused part: `INSERT` with `Tab next · Esc Esc cancel` in a field, `COMMAND` with `␣ toggle · ⏎ bind · Esc cancel` in the checklist | Render: RESOLVE on `bind-float` |
| FK13 | A key acts on the page under a float (`␣cn`, `␣.`, `␣ad`, `␣cx` under the outbox or a reply) | every float that takes the keys is a root context in `keymap.toml`: only its own keys act, with `Esc` (and `q` where it has no input) to close it, and its badge names its own mode | Unit: under each float, every key of `global` is inert; Render: DIM and the badge on `answer-conflict` and `unknown-outcome` |
